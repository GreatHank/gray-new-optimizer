# 大视场二值级次解耦优化器资料说明

## 1. 结论先行

这套资料描述的是一个基于二维衍射级次解耦的多通道远场全息优化原型。它用同一组二维相位梯度矩阵 `phdx`、`phdy`，在不同衍射级次 `(m,n)` 上生成不同目标图案。

当前提供的数据和代码属于**二值亮灭优化**，不是连续灰度优化：

- 目标数据共有 23 个通道，每个通道为 `500×500`；
- 数据类型为 `uint8`，实际取值只有 `0` 和 `1`；
- `0` 表示暗背景，`1` 表示目标亮线；
- 原始图案损失仍按每通道自身峰值归一化；主脚本现同时输出全通道统一曝光图和原始强度指标，用于跨通道比较亮区平均强度；
- 主脚本不生成相位 CSV、CIF、GDS 或 FDTD 内容；
- 任务书提出的 16 灰阶、180° 视场、FDTD 验证和 GDS 流程不在当前实现范围内。

文件夹中已有原始5000轮结果和亮区一致性5000轮实验结果，可以验证软件模型内的图案质量和跨通道亮区一致性；仍没有 FDTD 工程或实验测量，不能据此确认真实器件效率。

## 3. 任务书讲了什么

任务书给出的完整方向比现有代码更大，主要包括：

1. 参考论文 *Multidimensional-Encrypted Meta-Optics Storage Empowered by Diffraction-Order Decoupling* 中的级次解耦原理，并从一维扩展到二维，即同时利用 x、y 方向衍射级次。
2. 设计大视场远场全息，目标视场写为 180°，目标灰度写为 16 个台阶。
3. 整理现有梯度下降代码，重点加入权重自适应调节和可视化。
4. 先完成简单大视场图案的相位优化，再处理更复杂图案。
5. 将优化相位转换为器件版图，导入 FDTD 验证远场全息效果。
6. 进一步比较：更多衍射级次配合大周期，还是较少级次配合小周期更合适；灰阶数与性能、计算资源怎样折中；除大角度斜入射外，能否采用垂直入射编码。

任务书末尾还附有一张个人课表，用于说明可联系时间，与算法本身无关。

## 4. 核心算法原理

### 4.1 两张共享相位梯度图

优化变量是两张 `500×500` 的实数矩阵：

- `dx = phdx`：x 方向相位梯度；
- `dy = phdy`：y 方向相位梯度。

它们随机初始化到 `[0,2π)`，随机种子固定为 `42`，再由 Adam 优化器更新。代码参数为：

- 迭代次数：`30000`；
- 学习率：`5×10^-4`；
- 设备：优先 CUDA，否则 CPU。

### 4.2 不同衍射级次生成不同图案

对第 `c` 个通道，其衍射级次为 `(m_c,n_c)`，对应复场为：

```text
φ_c(x,y) = m_c · dx(x,y) + n_c · dy(x,y)
U_c(x,y) = exp(i · φ_c(x,y))
I_c = |fftshift(FFT2(U_c))|²
```

同一组 `dx/dy` 被所有通道共享，但不同 `(m,n)` 会形成不同的线性相位组合，因此可以让不同衍射级次承载不同图案。这就是代码中“级次解耦”的核心。

当前 23 个级次按以下顺序使用：

```text
(3,-3), (2,-3), (1,-3),
(3,-2), (2,-2), (1,-2), (0,-2),
(3,-1), (2,-1), (1,-1), (0,-1),
(3, 0), (2, 0), (1, 0),
(3, 1), (2, 1), (1, 1),
(3, 2), (2, 2), (1, 2),
(3, 3), (2, 3), (1, 3)
```

### 4.3 效率与图案误差

代码把目标亮区内的能量占比定义为通道效率：

```text
η_c = 目标值为 1 的像素中的远场能量 / 全部远场能量
```

随后将每个通道的远场强度除以该通道自身最大值，目标也除以自身最大值，再计算所有像素的平方误差。单通道损失近似为：

```text
L_c = w_c · [8(1-η_c)]³ · Σ(I_c,norm - T_c,norm)²
```

总损失为 23 个通道损失之和。`w_c` 是手工指定的通道权重，用来调整不同通道在总损失中的占比。

需要注意：效率因子与图案误差是相乘关系。高效率会直接缩小整个图案误差项，所以它并不是“图案误差 + 独立效率约束”这种可分别解释的目标。

## 5. 目标数据实际是什么

`grayscale_image.mat` 中只有变量 `bw_all`：

| 属性 | 实际值 |
|---|---|
| 形状 | `(23, 500, 500)` |
| 数据类型 | `uint8` |
| 最小值 / 最大值 | `0 / 1` |
| 不同取值数量 | 2 |
| 单通道亮像素占比 | 约 `0.6500%` 至 `1.2312%` |

23 张图是稀疏的白色蔬果轮廓，分别放在画面不同边缘或角落。也就是说，代码当前要解决的是“某处亮、其余位置灭”的多通道二值图案生成。

它与真正灰度优化的区别是：

- 没有 0 与 1 之间的中间目标值；
- 没有 16 个灰度台阶；
- 没有公共灰度响应曲线；
- 各通道独立按峰值归一化，无法据此比较通道间原始亮度；
- 训练中的手工权重只改变优化关注程度，不等于结构真实产生了相应的通道功率。

## 6. 各脚本的具体流程

### 6.1 `order_decoupling_grayscale.py`

当前流程为：

```text
读取 bw_all
  → 建立 23 个目标和 23 个 (m,n) 级次
  → 随机初始化 phdx/phdy
  → 每轮逐通道计算 FFT、效率和二值图案误差
  → 可选：约束23个通道目标白色像素的原始平均强度一致，并保护最差通道
  → Adam 更新共享 phdx/phdy
  → 保存 optimized_results.npz
  → 输出 target_vs_optimized_0_1.png
  → 输出统一曝光图和 channel_brightness_metrics.csv
  → 结束
```

保存的 NPZ 包含相位矩阵、损失历史、级次表、权重、目标数据、原始远场、逐通道归一化远场、统一曝光远场、效率历史和亮度一致性历史。`target_vs_optimized_0_1.png` 继续用于看单通道形状；`target_vs_optimized_global_scale.png` 对所有通道使用同一最大值；`channel_brightness_metrics.csv` 报告亮区均值、背景均值、目标区效率和对比度。流程到此结束，不再保存供 CIF 使用的 `phdx.csv`、`phdy.csv`。

运行正式优化：

```powershell
python .\大创资料\order_decoupling_grayscale.py
```

先用少量轮数检查流程：

```powershell
python .\大创资料\order_decoupling_grayscale.py --epochs 1 --output-dir .\大创资料\smoke_result
```

`--output-dir` 必须指向尚不存在的目录，避免误覆盖已有结果。

运行跨通道亮区一致性实验：

```powershell
python .\大创资料\order_decoupling_grayscale.py `
  --epochs 5000 `
  --device cuda `
  --brightness-consistency-weight 1.0 `
  --worst-channel-weight 1.0 `
  --output-dir .\大创资料\result_brightness_consistency_5000
```

一致性指标使用每个通道目标白色像素的原始平均强度，再除以该通道全平面平均强度。由于当前单位模近场使各通道全平面总量相同，这个无量纲量的跨通道相等就等价于原始亮区平均强度相等。原有图案损失同时保留，防止只追求一致而完全放弃目标形状。

### 5000 轮实际运行结果

2026-08-23 使用 CUDA、默认随机种子和默认学习率完成 5000 轮运行，结果目录为 `result_apple_pear_5000/`：

- 初始损失：`2.317498×10^8`；
- 最终损失：`7.563983×10^7`；
- 0-1 归一化 MSE：`0.007416`；
- 目标线条平均响应 / 背景平均响应：`9.02`；
- 苹果、梨等 23 个目标轮廓均已可辨认，但部分通道亮度仍偏低。

### 亮区一致性5000轮实验

完整数学定义、梯度机制和输出说明见 [跨通道亮区一致性优化算法](./跨通道亮区一致性优化算法.md)。

2026-08-26 使用相同随机种子、学习率和5000轮数，增加亮区一致性权重 `1.0` 与最差通道权重 `1.0`，结果位于 `result_brightness_consistency_5000/`：

| 指标 | 原5000轮 | 一致性5000轮 |
|---|---:|---:|
| 23通道亮区平均强度 CV | `45.43%` | `2.26%` |
| 最亮/最暗亮区均值跨度 | `6.089×` | `1.073×` |
| 最差图案/背景对比度 | `2.78` | `6.89` |
| 平均图案/背景对比度 | `8.85` | `7.08` |
| 逐通道归一化平均 MSE | `0.007416` | `0.007919` |

这说明在当前软件前向模型中，可以用小幅平均图案误差代价换取显著更一致的目标亮线强度，同时改善原本最暗通道。该结论不等于真实器件的23个衍射级次具有相同绝对功率；真实级次效率仍需联合物理模型或实验测量。

### 6.2 `show_save_img.py`

该脚本重新计算每个级次的远场，并输出：

- 目标图合集 `targets.png`；
- 每通道峰值归一化远场 `holograms_normalized.png`；
- 绝对强度显示图 `holograms_absolute.png`；
- 每个通道的绝对/归一化强度 CSV；
- 损失曲线 `loss_curve.png`；
- 各通道效率曲线和最终效率 CSV。

其中“绝对强度图”仍由 Matplotlib 对每个子图自动选择显示范围，适合查看形状，但不能直接作为跨通道绝对亮度一致性的验收图。

### 6.3 `calculate_weight.py`

脚本使用 9 个已测强度和 9 个旧权重，按下式进行一次离线补偿：

```text
新权重 = 旧权重 × 最大测得强度 / 当前通道测得强度
```

现有数据计算结果为：

```text
[12.19, 7.71, 9.78, 5.99, 5.43, 18.17, 7.00, 4.05, 7.41]
```

这只是人工重新计算权重的辅助脚本，不是会在训练过程中自动测量、更新并收敛的自适应权重机制；通道数也与当前 23 通道不一致。

### 6.4 `mask_generate.m`

MATLAB 脚本设定：

- 阵列大小：`500×500`；
- 入射波长：`480 nm`；
- x/y 周期：`850 nm`；
- 方形纳米砖：`145 nm × 145 nm`。

它先把相位取模到 `[0,2π)`，再映射成单周期内的 XY 位移：

```text
Δx = mod(phdx / 2π · p_x, p_x)
Δy = mod(phdy / 2π · p_y, p_y)
```

之后为 25 万个单元逐个写入一个方形多边形，生成 CIF 文件。该映射与优化器中的 `m·phdx+n·phdy` 形式在理想位移相位模型下相互对应。

## 7. 当前运行边界

### 7.1 已修复的直接错误

1. 原有两个非法 `assert` 已替换为带清晰错误信息的输入校验。
2. 默认输入已改为脚本同目录下实际存在的 `grayscale_image.mat`。
3. 目标、级次数量、权重数量和二值取值会在优化前验证。
4. 对比图已并入主脚本，不再依赖写死旧结果目录的 `show_save_img.py`。
5. 主流程不再输出 `phdx.csv`、`phdy.csv`，因此不会进入 `mask_generate.m` 的 CIF 流程。

### 7.2 尚未证明或尚未实现的部分

- 没有 16 灰阶目标数据和相应灰度损失；
- 没有代码计算或验证 180° 视场；
- `mask_generate.m` 中的 `lambda=480 nm` 没有参与任何计算；
- 没有检查给定周期、波长和最高三级衍射是否满足传播条件；
- 没有 FDTD 模型、材料参数、边界条件、光源设置或仿真结果；
- 没有 GDS 导出；
- 没有检查纳米砖移位后是否跨单元或与相邻图形重叠；
- 没有制造约束、最小间距、偏振响应、耦合和加工误差模型；
- 正式 30000 轮结果仍需实际运行后核对成像质量和收敛情况。

### 7.3 计算量问题

每一轮训练会顺序执行 23 次 `500×500` 的二维 FFT，共训练 30000 轮，即约 69 万次二维 FFT，且 Python 循环内每个通道都会执行一次 `eta.item()` 的设备同步。现有代码没有通道批处理、显存/运行时间评估或断点续训，正式运行前需要先做小轮数性能测试。
